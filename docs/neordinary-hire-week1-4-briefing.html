1주차 — 문제 정의 / 가설 / 시장 방향

문제를 “채용 플랫폼 부족”이 아니라 “커뮤니티 evidence가 파트너 검토 단위로 번역되지 않는 문제”로 좁혔습니다.

WEEK 1
핵심 문제

검증된 활동 evidence는 있지만, 검토 가능한 표준 형식이 없다

커뮤니티 기반 인재의 실제 역량은 프로젝트, 협업, 운영 참여, 성장 기록에 드러나지만 파트너가 빠르고 안전하게 검토할 수 있는 방식으로 정리되어 있지 않습니다.

해결 방향

익명 후보 카드 + 루브릭 + 중개 플로우

운영자가 검수한 evidence를 익명 후보 카드로 변환하고, 파트너가 shortlist/inquiry를 남기면 후보 동의와 운영자 중개 후 다음 단계로 연결합니다.

문제 원인

  • 후보의 실력은 이력서보다 프로젝트, 협업, 운영 참여, 성장 기록에 더 잘 드러납니다.
  • 하지만 해당 evidence는 여러 문서, 포트폴리오, 운영자 기억, 활동 로그에 흩어져 있습니다.
  • 원본을 그대로 파트너에게 제공하면 개인정보, 맥락 노이즈, 검토 부담이 생깁니다.
  • 운영자 추천은 신뢰도가 높지만 반복 가능한 제품 경험으로 확장되기 어렵습니다.
커뮤니티 안에서 발견된 가능성을 파트너가 검토 가능한 단위로 번역한다.
가설익명 후보 카드가 있으면 파트너는 신원 정보 없이도 1차 관심 여부를 판단할 수 있다.
기대 효과파트너 검토 시간 감소, 후보 조기 신원 노출 방지, 운영 추천의 반복 가능성 확보.
보정 포인트“후보 DB 공개”가 아니라 “익명·검수·중개 기반 evidence review workflow”로 정의합니다.

2주차 — 경쟁사 분석 / 유저 리서치

경쟁사는 일반 채용 플랫폼뿐 아니라 지인 추천, 커뮤니티 운영자 추천, ATS/HR SaaS까지 포함해 봐야 합니다.

WEEK 2
직접 경쟁

개발자·주니어 채용 플랫폼

이력서와 신원 기반 탐색에 강하지만, 커뮤니티 안의 실제 협업 evidence를 충분히 담기 어렵습니다.

간접 경쟁

지인 추천·운영자 수동 추천

신뢰도는 높지만 반복 가능한 비교, 검색, 상태 관리, 파트너 공유 경험이 약합니다.

잠재 경쟁

HR SaaS·ATS·교육기관 연계

내부 채용 관리에는 강하지만 community-origin evidence를 파트너 안전 카드로 변환하는 데는 약합니다.

벤치마킹 요소

  • 카드형 후보 정보 구조
  • 비교 가능한 필드와 태그
  • shortlist 기능과 문의 CTA
  • 추천 근거/evidence summary
  • 검수 상태와 공개 가능 범위 표시

유저 리서치 우선순위

1순위 사용자파트너 리뷰어 — 후보를 빠르게 검토하고, 관심 후보에만 문의하고 싶은 사용자.
2순위 사용자커뮤니티 후보 — 활동 evidence는 있지만 신원/연락처가 무분별하게 공개되길 원하지 않는 사용자.
핵심 검증파트너가 이름/연락처 없이 후보 카드만으로 1차 관심 판단을 할 수 있는가.
핵심 질문
  1. 파트너는 후보를 볼 때 어떤 근거를 가장 먼저 보는가?
  2. 이름/연락처 없이도 1차 관심 판단이 가능한가?
  3. 문의 전 반드시 필요한 정보는 무엇인가?
  4. 후보는 어떤 활동 정보까지 익명 공개를 허용할 수 있는가?
  5. 어떤 조건에서 신원/연락처 공개에 동의할 수 있는가?

3주차 — 서비스 정의 / 페르소나 / 전략 / 비즈니스 모델

서비스의 중심을 “파트너 리뷰어가 신뢰 가능한 후보 evidence를 빠르게 판단하는 경험”으로 잡았습니다.

커뮤니티 기반 후보

  • 프로젝트, 스터디, 운영 참여 등 실제 활동 경험이 있음
  • 이력서로 자신을 충분히 설명하기 어려움
  • 정보가 무분별하게 공개되는 것을 원하지 않음

핵심 기능

1. 익명 후보 카드

이름, 연락처, 민감 정보 없이 역량 evidence 중심으로 후보를 검토합니다.

2. 운영자 검수 evidence summary

프로젝트, 역할, 협업 방식, 성장 기록을 파트너가 이해하기 쉽게 요약합니다.

3. shortlist / inquiry

파트너가 관심 후보를 저장하고 조건이 맞을 때 문의할 수 있습니다.

4. 후보 동의 기반 신원 공개

파트너 문의 후 후보가 동의해야 신원과 연락처가 공개됩니다.

해결책익명 후보 카드, evidence summary, shortlist/inquiry, 동의 기반 공개.
