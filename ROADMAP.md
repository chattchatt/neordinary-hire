# ROADMAP.md

## Product roadmap

### Phase 0 — Baseline product SOT

- Replace generic project docs with product operating docs.
- Add issue/PR templates.
- Add labels and first sprint issues.
- Keep confidential strategy in private workspaces; keep GitHub focused on execution.
- Maintain `docs/product-planning-sot.md` and `DESIGN.md` as planning/design gates before expanding implementation scope.

### Phase 1 — Company Review MVP

Goal: partners can review anonymized candidates and request next steps.

- Company candidate detail page
- Shortlist save flow
- Inquiry CTA
- Score explanation
- Privacy exposure verification

### Phase 2 — Evidence quality

Goal: candidate profiles become more trustworthy through curated evidence.

- Drive evidence summary improvements
- Discord activity summary quality checks
- Evidence confidence labels
- Operator review queue for uncertain matches

### Phase 3 — Talent registration quality

Goal: registration captures enough information with less friction.

- Improve quick registration copy and completion
- Consent and privacy clarity
- Duplicate-click/rate-limit hardening
- Success-state guidance

### Phase 4 — Partner pilot operations

Goal: turn review sessions into repeatable partner workflow.

- Partner-specific shortlist export or report
- Inquiry routing and response SLA
- Pilot review notes
- Metrics review and micro-pivot decisions
